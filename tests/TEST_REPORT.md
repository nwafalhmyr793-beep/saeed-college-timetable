# تقرير اختبار النسخة المستقلة

التاريخ: 2026-10-08، بتوقيت عدن. اختُبرت نسخة GitHub المستقلة بعد التصحيحات وتحديث الحزم. بيئة التشغيل: Linux، Node.js 24.19.0، pnpm 11.25.0، Cloudflare Workers محليًا عبر Wrangler 4.92.0.

## النتيجة

اجتازت النسخة 81 حالة اختبار مسماة، إضافة إلى مجموعة صلاحيات المدرسين الأصلية. هذه نتيجة للحدود المبينة أدناه، وليست إثباتًا لغياب جميع العيوب أو الثغرات.

## التصحيحات التي أثبتتها الاختبارات

- الطلبات ذات JSON التالف أو الجسم null أو المصفوفة تُرفض برمز 400، بدل أخطاء 503.
- أسماء المستخدمين المفقودة وقيم التفعيل والصلاحيات غير المنطقية تُرفض قبل تعديل الحساب.
- حفظ المدرس أو الحساب من النموذج الذي يرسل id فارغًا يعمل بصورة صحيحة.
- تواريخ مثل 2026-02-30، وأوقات مثل 24:00 و08:60، والأقسام غير المعروفة، والمقرر الفارغ تُرفض.
- «403» و«قاعة 403» و«قاعه 403» و«ق 403» تُحسب قاعة واحدة، وكذلك صيغ Cisco.
- تغيير المكان واستعادة المكان الأصلي يتحققان من الحجز في التاريخ والفترة نفسيهما.
- فلاتر المستوى غير الصحيحة في سجل العمليات تُرفض برمز 400.
- تحسنت أنواع البيانات في المصدر، وأُزيلت أخطاء التحليل البرمجي والحقول غير المستخدمة، وحُدثت الحزم التي لها إصدارات أمنية مصححة مع إعادة اختبار التوافق.

## ما اختُبر على الخادم الفعلي

- المواعيد الأساسية الـ614 فريدة وصالحة، والبيانات الخاصة لا تُرسل للزائر.
- إنشاء المديرين للحساب الرئيسي وحده، وإنشاء المدرسين والمناديب وإسناد المحاضرات.
- تسجيل الدخول وكوكي الجلسة، ورفض كلمات المرور الخاطئة والجلسات المنتهية والمزيفة، ومنع طلبات التعديل من أصل خارجي.
- عدم منح أي صلاحية لهوية ChatGPT المرسلة في ترويسات الطلب، وعدم وجود مسار دخول خارجي.
- معاينة الإلغاء وفق القسم والأسبوع، ورفض المحاضرات غير المسندة للمدرس.
- خمسة طلبات إلغاء متزامنة لنفس المحاضرة أنتجت إشعارًا واحدًا وحدث إلغاء واحدًا في السجل في الاختبار.
- توجيه الإشعارات إلى مندوب القسم والمستوى الصحيحين، ورفض قراءة إشعار مندوب آخر، والتعليم كمقروء.
- إلغاء الأسبوع واستعادته عبر قسمين، وبقاء الأسبوع التالي قائمًا.
- تعديل اسم المدرس ولقبه، وتعطيل حسابه وإبطال جلسته، ثم إعادة تفعيله.
- 25 طلب قراءة متوازيًا بحسابات مختلفة حافظت على فصل الأدوار؛ هذا فحص محدود، وليس قياس تحمل للإنتاج.
- تغيير كلمة المرور أبطل الجلسات؛ استمر الحساب والبيانات وكلمة المرور الجديدة بعد إعادة تشغيل الخادم، دون إعادة ضبطها بسر التهيئة القديم.
- صفحات الجدول والدخول والإدارة وملفاتها المحلية تُقدَّم عبر HTTP بصورة صحيحة، وتوليد مكونات الإدارة يقيّد أدواتها حسب الدور ويهرب النصوص المدخلة.

## الاعتمادات

قبل التحديث سجّل pnpm audit: حرجًا واحدًا، و30 مرتفعًا، و23 متوسطًا، و8 منخفضة. بعد التحديث: لا حرج أو متوسط أو منخفض، ومرتفع واحد متبقٍ. هذه أعداد نتائج أداة التدقيق، وليست عدد عيوب مؤكدة قابلة للاستغلال في التطبيق.

تحديثات أساسية: Next.js وeslint-config-next إلى 16.3.8، وReact وReact DOM وReact Server DOM إلى 19.2.8، وVite إلى 8.0.16. ثُبتت تصحيحات الاعتمادات التابعة في pnpm-workspace.yaml وملف القفل؛ سياسة التحقق من الحزم وعمر الإصدار بقيت مفعلة.

التنبيه المتبقي: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)، في braces 3.0.3 عبر fast-glob/micromatch في أدوات ESLint وVinext. لا يُمرر التطبيق مدخلات الطلبات إلى هذه المكتبة. لا يمكن اعتبار فحص الحزم الكامل ناجحًا ما دام التنبيه قائمًا، ولا يُخفى باستثناء من التدقيق.

بيانات الفحص المختصرة في [audit-summary.json](audit-summary.json). التحديثات واختبارات الخادم تمت على نسخة مستقلة وقاعدة اختبار مؤقتة، دون تعديل حسابات أو بيانات الموقع المنشور.

## حدود الاختبار

- لم يُنفذ اختبار تفاعلي داخل متصفح أو فحص بصري لأحجام الهاتف وسطح المكتب؛ المتصفح غير مثبت وتعذر تنزيله. اختبارات المكونات تتحقق من HTML والمنطق المشروط، ولا تتحقق من النقر والتمرير أو CSS أو إتاحة الاستخدام الكاملة.
- لم يُختبر نشر فعلي إلى حساب Cloudflare خاص بالمستخدم، أو بيانات الإنتاج، أو النطاق وTLS هناك؛ تم اختبار تجهيز النشر محليًا فقط.
- الاختبارات لا تمثل اختبار اختراق خارجيًا، أو اختبار تحمل مطولًا، أو ضمانًا لعمل كل إصدارات Node.js وكل المتصفحات وأنظمة التشغيل.

## إعادة التنفيذ

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm test:integration
pnpm db:generate
pnpm peers check
pnpm audit
pnpm audit --prod
```

رمز الخروج غير الصفري من pnpm audit متوقع للتنبيه المتبقي أعلاه. اختبارات التكامل تستخدم بيانات مؤقتة وتزيلها بعد الانتهاء.
